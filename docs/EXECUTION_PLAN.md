# ModLudus 执行计划

## M0（当前）

完成产品验收页面、项目骨架、配置模板和 API 健康检查。

## M1（1–2 周）

接入通用 OpenAI-compatible endpoint，完成模型发现、连接测试、候选并行调用和运行记录。

## M2（已验收）

已完成浏览器内 CSV/JSONL 导入、Rubric 版本快照、标准赛季 2026.1、逐题批量运行、失败题重试、分层人工抽检队列和 JSON/CSV/HTML 本地报告。当前批量执行使用题目串行、题内候选并行，避免瞬时压垮用户网关。


## M3.1（已验收）

加入在途请求取消、题目并发 1–4 配置、脱敏 Session Storage 恢复点、数据集/模型配置指纹校验和未完成题续跑。模型配置指纹包含规范化 Base URL 的随机加盐哈希，能够阻止相同 Model ID 跨网关混批；恢复点不保存 Key、Base URL 原文、测试题或模型答案。只有 Session Storage 实际写入成功时，界面才提示可刷新恢复。

## M3.2（已验收）

加入服务器管理员配置的可信赛季执行器，冻结标准赛季运行清单、运行环境与模拟标识；保存不可变证据哈希、Ed25519 签名报告与 append-only 审计链。浏览器用户 Key 不进入该链路。付费启动接口使用管理员令牌保护，本地免鉴权必须显式开启且只接受回环请求。

## M3.3（当前纵向切片）

可信运行改为共享证据卷上的持久任务租约，由独立 Worker 领取、续租和恢复；API 重启不再终止任务，Worker 租约过期会重新排队，重试耗尽才失败。Worker `attempt` 作为 fencing token，旧租约不能写入进度、失败或证据。加入独立复核令牌、追加式批量复核决定，以及可信赛季榜发布门禁：只有 official、非模拟、验签通过且必要复核闭环的运行可以发布。`overturned` 在尚无修正排名结构时保持未闭环；发布冻结 review snapshot 且锁定后续复核。首版保持单机 SQLite/WAL 任务真相源，Redis/PostgreSQL 集群化迁移放到后续增强，不把当前实现描述成分布式队列。

## M4（后续）

接入 Redis/PostgreSQL 持久任务后端、EvalScope、回归门禁、细粒度身份权限、备份恢复和正式 HTTPS 部署。
