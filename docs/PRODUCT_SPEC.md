# ModLudus 产品立项

## 定位

基于真实业务任务的多模型竞技与智能选型平台。

## MVP

- 单轮文本：文案、代码、总结、数据分析
- 2–6 个 OpenAI-compatible 候选模型
- 匿名输出、随机 A/B 位置
- 一个独立裁判模型自动评分
- 10%–20% 人工抽检
- 质量、成本、速度和失败率
- 单机 Docker Compose，内部使用与小范围试点
- 默认浏览器直连网关，Key、测试集和结果不发送到 ModLudus 服务端
- 最多 6 个网关连接、总计 6 个候选模型；一个网关可选择多个模型
- 四类场景提供一键填充示例，降低首次使用门槛
- 页面预留匿名贡献模型指标的交互开关，但 M0/M1 原型不上传数据
- CSV/JSONL 本地批量测试集、Rubric 版本快照和失败题重试
- 失败、裁判异常、低置信度强制抽检，其余样本稳定抽样 20%
- JSON、CSV、单文件 HTML 报告仅在用户浏览器生成
- 标准赛季入口使用版本化内置题集；当前结果仍属于客户端运行，不等同可信官方榜单
- 批量任务可取消，题目并发 1–4 可配置，支持刷新后匹配恢复脱敏结果并继续未完成题目
- 可信赛季由服务器冻结并执行固定测试集、Rubric、模型和价格快照，输出签名报告与审计记录

## 不在 MVP

多轮状态、多模态、Agent 工具调用、SaaS 多租户、双裁判、自动生产路由和复杂 GPU 调度。

## 质量原则

自动裁判是决策辅助而非事实真值。低置信度、裁判/人工分歧和高价值样本必须保留人工复核入口。推荐结果展示 Pareto 前沿，不固化为永久单一冠军。

## 隐私承诺

默认模式不持久化 API Key、Base URL 原文、Prompt、测试集、模型输出和裁判原文。M3.1 只在当前标签页 Session Storage 保存可删除的脱敏恢复点：指纹、配置随机盐、Rubric、评分、Token、延迟、参考成本和复核状态。规范化 Base URL 仅参与加盐配置指纹计算，用于防止跨网关混批。浏览器请求直接发送至用户配置的模型网关。若网关不支持 CORS，后续提供本机临时代理，不经过平台云端。

M3.2 可信赛季是独立的服务器模式，只使用平台管理员在部署环境中配置的模型凭据，不读取用户浏览器的连接配置。付费启动操作需要管理员授权；读接口可公开用于验签。签名报告冻结运行环境与模拟标识，不包含凭据、网关原文、Prompt 或模型输出原文；内容只以哈希和结构化指标进入不可变证据。

M3.3 把可信运行放入独立持久 Worker，并增加人工复核权限和赛季榜发布治理。模拟或非 official 证据只能用于本地验收与内部分析，不能进入公开可信榜；所有必要复核必须先形成追加式闭环决定。首版的 `overturned` 仅标记异议并继续阻断发布；发布时冻结复核快照哈希和榜单排名，发布后复核锁定。

M4.1 增加可信证据灾难恢复能力。备份在本机或受控服务器内生成，不通过产品网页下载；归档包含 SQLite 证据库和保持历史签名连续性的 Ed25519 私钥，因此必须加密保管。系统允许独立验证归档，但恢复只写入空目录，不允许一条命令覆盖正在运行的证据卷。

模型天梯允许普通客户手动更新 OpenRouter 与 Artificial Analysis 两个固定公开来源，但限频属于全站共享而非单个浏览器：任一用户成功更新后，其他用户在 24 小时内只能读取同一快照，并看到“今日已更新”和下次可更新时间。OpenRouter 决定当前模型目录；AA 只补充能够透明映射的外部指标。更新失败不得清空旧榜单，也不能把旧数据重新标记为刚更新。

天梯贡献默认关闭，当前原型没有上传实现。后续启用时也只允许贡献模型 ID、场景类型、胜负、裁判评分、Token 和性能区间，不上传 Base URL、API Key、原始题目或模型答案。社区贡献榜必须标记为“体验榜”；可信排名使用固定测试集和可审计规则生成“标准赛季榜”。
